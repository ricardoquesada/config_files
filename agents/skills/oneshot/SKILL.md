## Phase 1: Clarification

1.  Create a detailed design document and task list mapping out all the steps
    required by this skill.
2.  Spawn 3 identical subagents ("Assessor 1", "Assessor 2", "Assessor 3").
3.  Send each the user's goal (including any answers from previous iterations)
    and this prompt: `Analyze the request to find loopholes, missing edge cases,
    architectural risks, and verification gaps. Identify: - Functional edge
    cases or underspecified behavior. - Technical unknowns (cross-system
    impacts, unclear dependencies). - Verification strategy (what tests are
    needed). Propose ONLY questions that are absolutely necessary to resolve
    ambiguities before implementation. If you believe the request is already
    extremely clear and no questions are needed, explicitly state that you are
    ready to proceed or return 'ALL_CLEAR'.`
4.  Wait for all 3 to return analysis.
5.  Consolidate feedback and remove duplicates.
6.  If NO questions were generated by any assessor (or if all responded that
    they are ready to proceed), proceed to Phase 2.
7.  Otherwise, present the consolidated necessary questions to the user using
    the `ask_question` tool. (Ensure they are structured according to the tool's
    requirements).
8.  Wait for the user's answer. If the assessors believe all requirements are
    clarified, or if a maximum of 3 iterations has been reached, proceed to
    Phase 2. Otherwise, repeat the assessment (Steps 2-9) with the updated
    context. If the user asks a counter-question, answer it, but ensure the core
    technical questions are resolved before moving to Phase 2.

## Phase 2: Implementation

1.  Outline your design document in a markdown Artifact as required by general
    agent rules. You MUST set `RequestFeedback: true` in the Artifact metadata
    so a 'Proceed' button is rendered for the user.
2.  Wait for the user to click 'Proceed' or explicitly approve the design. Do
    NOT make any code edits until this is done.
3.  Once the design is approved, implement the design by editing the code and
    writing required unit tests.
4.  Run `hg fix` and `build_cleaner` as dictated by project rules.
5.  Summarize all your code changes for the user's review. Do NOT create a CL.
